# Example: Ground-up UI rebuild request

Use `ui-slop` to rebuild this product's frontend from first principles.

First identify and document the protected product contract from the implementation, tests, routes, data, and requirements.

Treat the current presentation layer as disposable unless a presentation behavior is itself part of the product contract.

You may remove, replace, merge, or restructure existing UI elements.

Build a new information architecture, visual system, layout, typography system, and motion language.

Reject generic AI-dashboard patterns and unnecessary explanatory copy.

Use any relevant available design/frontend/browser/accessibility/performance skills or plugins. Discover additional capabilities when the environment permits it.

Run the actual product in a browser and iterate until the result is visually coherent, responsive, accessible, performant, and materially different from the old presentation.

Do not declare completion from automated tests alone.
