# Presentation Rhythm

Use this to coordinate typography, information density, spacing, and simultaneous visibility.

The goal is neither maximum density nor maximum whitespace.

The goal is a working surface where **importance, readability, and information capacity reinforce each other**.

## Set an information budget

For each important viewport, decide what deserves simultaneous visibility.

Classify information as:

- primary: needed for the current decision or task
- supporting: useful in the same glance
- contextual: useful when the object is selected or investigated
- deferred: useful later, but not worth permanent attention cost

Do not show everything because space exists.

Do not hide useful working information because empty space looks premium.

## Compress information before shrinking type

When a surface feels too sparse or too large, improve density in this order when appropriate:

1. remove duplicate labels and repeated explanation
2. group related information more efficiently
3. align comparable values
4. share context instead of repeating it per item
5. shorten redundant phrasing
6. use a better representation for repeated structure
7. use progressive disclosure for genuinely secondary detail
8. tighten spacing where the relationship supports it
9. only then consider smaller typography

Do not buy density primarily with microtype.

## Typography role economy

Use the fewest typographic roles that make hierarchy unmistakable.

A typical working product may need only:

- primary/task title
- reading/body
- controls/labels
- metadata/data
- optional identifier or display role when the content justifies it

Do not create a new visual treatment for every semantic subtype.

Repeated roles should remain stable across states and screens.

## Microtype is not a hierarchy system

Small text can be appropriate for genuinely secondary metadata.

It becomes a failure when large portions of the working viewport turn into visual texture.

Warning signs:

- most labels are 10–12px
- uppercase + tracking is doing most of the distinction work
- condensed type is used mainly to fit more UI
- important secondary context becomes tiring to read
- mobile keeps desktop microtype instead of restructuring information

As a review heuristic, if the majority of visible working copy on desktop is around 12px or smaller, inspect whether density has been purchased through legibility loss.

This is a warning, not a universal numeric ban.

## Body and reading comfort

Primary reading text should normally remain around ordinary browser body scale or equivalent unless the product has a strong dense-interface reason.

Dense controls and metadata may be smaller, but their role must be truly secondary and still readable at real scale.

Test the actual face, weight, contrast, line height, and viewport. A nominal size alone cannot prove readability.

## Spatial rhythm

Use contrast between tight and generous spacing to communicate relationship.

Avoid both:

- one spacing value repeated everywhere
- arbitrary spacing changes added for visual variety

Tight spacing should signal belonging.
Generous spacing should signal a meaningful boundary or focus shift.

## Density by region

A product does not need one global density.

Examples:

- index/list can be compact
- evidence reading can breathe more
- comparison can be dense but aligned
- navigation can remain quiet
- transient detail can prioritize comprehension over simultaneous visibility

Use density changes to support the task rather than to decorate sections.

## Viewport utilization

On wide screens, ask whether empty regions are intentional focus or unused capacity.

On narrow screens, ask whether stacking has created an endless document.

A strong responsive transformation may:

- reorder information
- summarize secondary context
- move comparison into a dedicated mode
- preserve one working object at a time
- keep high-frequency actions persistent

Do not preserve desktop density by shrinking everything.

## Typography and density are one system

When changing type, re-evaluate spacing and simultaneous visibility.

When changing density, re-evaluate type roles.

Do not optimize these independently.

A compact surface with comfortable type often requires better grouping and less repeated chrome.

## Presentation-rhythm audit

At desktop and mobile, inspect at real scale:

- percentage of attention spent on primary versus metadata
- whether body/reading text feels comfortable
- whether the same microtype treatment carries unrelated roles
- whether the first viewport contains enough working information
- whether any region is empty without purpose
- whether any region is dense only because type was shrunk
- whether spacing cadence helps scanning
- whether mobile changes information priority rather than only dimensions

A polished surface should feel information-rich where the work demands it and calm where comprehension demands it.
