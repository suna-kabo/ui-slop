# Quality Bar

This is a positive readiness bar, not a style score.

The target is not universal perfection. The target is that no material part of the primary experience feels obviously wrong.

## Readiness

A substantial surface is ready only when:

- Evidence Gate has no unresolved hard failure
- required evidence is not silently unknown
- the selected concept still solves the shaped problem
- no unresolved quality veto remains
- the weakest visible region is within the quality range of the strongest
- the primary experience remains strong on relevant platforms and inputs

## What counts as a material quality issue

A material issue is observable and explainable as harm to one or more:

- trust
- comprehension
- agency
- continuity
- visual quality
- repeated-use efficiency
- intended feeling
- platform fit
- performance perception

Personal preference alone is not material.

## Attention

Inspect the first useful viewport and primary states.

Reject when:

- labels, badges, numbering, institutional chrome, or helper copy compete with the primary object
- several elements demand equal emphasis
- negative space is accidental rather than focusing or pacing
- decorative authenticity tokens replace actual hierarchy
- the main action is visually secondary to explanatory UI

Every element must earn attention.

## Editing

Remove text or chrome when hierarchy, adjacency, imagery, behavior, or conventional semantics already communicate the meaning.

Keep secondary content when it:

- changes a decision
- clarifies state
- prevents error
- supplies provenance or context unavailable elsewhere
- enables action

Repeated description is not editorial depth.

## Secondary labels, descriptions, and eyebrow text

Secondary labels are not automatically wrong, but they are a high-risk support layer rather than a default visual ingredient.

This includes:

- eyebrows, kickers, overlines, and small uppercase labels
- section numbers and figure labels
- category, type, mode, and status descriptors
- helper descriptions and explanatory subtitles
- institutional, archive, source, or provenance labels
- captions that repeat nearby content

For every visible instance, name its unique job. Then run a subtraction test: temporarily remove it and restore it only when removal creates real ambiguity, hides state, weakens a decision, removes necessary provenance, increases error risk, or makes an action meaningfully harder to discover.

Reject when:

- a descriptor stack appears before the primary content, such as section number + eyebrow + type + mode + title
- a label names a page, section, object type, or mode that layout, title, control state, or imagery already makes clear
- a description paraphrases the heading or narrates what the composition already shows
- tiny uppercase or monospace text is used mainly to simulate premium, archival, technical, or editorial authenticity
- several labels express the same meaning at different levels
- supporting text visually outranks the object, task, or next action
- secondary copy compensates for weak hierarchy instead of supplying unique information

Keep it when it performs a necessary role such as:

- navigation or indexing that users actively use
- live status or mode that cannot be inferred safely
- category disambiguation among genuinely similar objects
- essential provenance, scope, units, constraints, or risk
- concise action guidance unavailable from the control or surrounding context

There is no universal ban and no fixed count. The test is unique information, earned attention, and actual user value.

## Composition

The viewport should read as one composition, not a collection of individually reasonable components.

Inspect:

- relationship between image/object and text
- dominant and supporting shapes
- crop and alignment
- tension and balance
- content rhythm
- transitions between dense and quiet regions
- whether wide space is used intentionally
- whether every section repeats one template

## Visual material

The chosen material must meet the fidelity implied by the direction.

This includes:

- photography
- illustration
- iconography
- 3D or procedural rendering
- diagrams
- maps
- charts
- texture
- video
- typography as image

A strong concept with placeholder-looking material is not ready.

Judge:

- silhouette
- proportion
- lighting or depth
- crop
- material credibility
- consistency
- resolution
- authorship
- relationship to content

## Typography

Inspect actual rendering, not token names.

Check:

- typeface suitability
- optical size and weight
- line length and line height
- tracking and case
- wrapping and orphaning
- baseline and cap-height alignment
- numeric stability
- responsive scaling
- contrast between display, body, utility, and data roles
- whether small uppercase or monospace labels are carrying too much hierarchy

A font pairing is not a typography system.

## Control locality and affordance

Controls should live where their relationship is obvious.

Reject:

- detached segmented controls when the object can be manipulated directly
- surfaces that look interactive but contain small isolated targets
- dead zones
- controls whose wording describes a mode rather than the action
- generic pill groups used to make an inert surface appear designed
- icon-only actions with weak discoverability

## Interaction response

For every primary action inspect the chain:

> input → acknowledgment → transition → state → next action

Response should begin promptly at the point of action.

Judge:

- press/focus/hover acknowledgment
- pending state
- local versus global response
- interruption and reversal
- boundary feedback
- state persistence
- next-action locality
- repeated-use comfort

A state variable changing after a click is not sufficient.

## Continuity

Open, close, select, filter, compare, reorder, save, navigate, and return should preserve the relationships the user needs.

Reject when:

- content appears from nowhere
- detail loses its origin without reason
- Back returns to the wrong state or position
- responsive transformation hides the active object
- focus and scroll contradict visual continuity
- a modal replaces a stronger object-anchored relationship by habit

## Motion

Motion must explain:

- cause and effect
- origin and destination
- hierarchy
- topology
- relationship
- progress
- completion

Decorative entrance, hover lift, image zoom, or universal fade/slide does not count as interaction quality.

Check:

- necessity
- immediate feedback
- natural weight
- interruption
- retargeting
- reduced motion
- repeated-use cost
- frame stability

An interface can animate and still feel dead.

## Responsive and platform fit

Do not review only layout width.

Inspect:

- content priority
- input method
- navigation model
- control placement
- crop
- density
- safe areas
- touch targets
- keyboard/focus
- sheet versus route versus inline detail
- motion distance and performance
- browser and device conventions

Mobile is not stacked desktop.

## Performance perception

Measure when possible and observe always.

Look for:

- delayed input acknowledgment
- long main-thread tasks
- dropped frames
- layout shifts
- font/image flashes
- unstable dimensions
- slow transitions used to hide work
- loading states that destroy structure

Fast completion cannot compensate for late feedback; smooth animation cannot compensate for delayed input.

## Weakest-link pass

Name the three weakest visible or interactive regions.

Fix the responsible system, not isolated pixels.

The result is not ready while one obvious quality cliff exposes the rest as unfinished.

## Ten-second veto

Give the first useful viewport and one primary interaction state to a skilled reviewer without explanation.

A veto is valid when they can point to a concrete issue and explain its harm.

Common vetoes:

- awkward gap
- unearned label
- stacked eyebrow or descriptor text
- repeated secondary description
- cheap asset
- generic modal
- detached action
- weak button
- accidental wrapping
- inconsistent radius or icon
- inert hover/press
- discontinuous transition
- mobile afterthought
- placeholder copy
- unexplained density
- visibly unfinished utility surface

Do not defend the issue with the design rationale before deciding whether the artifact actually communicates that rationale.
