# Origin Principles

UI Slop was generalized from a successful ground-up redesign contract used on a dense research product.

The reusable lessons were:

- protect product semantics, not accidental presentation
- simplify the interface rather than weakening domain logic
- allow radical presentation changes when the user grants redesign authority
- establish the workflow hierarchy before choosing components
- use a coherent design system rather than styling screens independently
- prefer restrained static visuals and polished interaction
- reject generic dashboard defaults
- remove defensive and implementation-facing copy
- audition typography in the real interface
- use motion for continuity, state change, and spatial understanding
- keep animation fast and performance-aware
- validate in the actual browser across real interactions and viewports
- let accessibility and performance shape the design
- update obsolete presentation-specific tests without weakening behavior
- use available design, frontend, browser, accessibility, and performance capabilities deliberately
- reject the agent's own work when browser evidence shows the design direction is weak

Product-specific domain rules from the original project are intentionally not part of this skill.
