# Product Principles

Use this after shaping and before detailed concept work.

Product principles are temporary decision tools for this product or surface. They are not universal design laws.

## Create three to five

Each principle should include:

- **Name**
- **Tension**
- **Decision rule**
- **Implication**
- **Rejects**

Example:

### Object before archive chrome

- Tension: object identity versus institutional context
- Decision rule: let the object dominate until archive metadata changes interpretation or action
- Implication: source and provenance remain available but do not compete in the opening composition
- Rejects: repeated labels that merely perform “museum authenticity”

## Good principles

Good principles:

- choose between credible alternatives
- reflect the user, domain, platform, and outcome
- apply to structure, behavior, and presentation
- survive a change in framework or component library
- create useful constraints
- can reject a plausible solution

Examples:

- Manipulate the route, not a detached form
- Comparison preserves the collection
- Evidence before certainty
- Quiet until consequence
- One-handed recovery
- The artifact earns the viewport
- Fast on the tenth use
- Detail returns to the exact working context

## Weak principles

Reject:

- clean and modern
- intuitive
- accessible
- use whitespace
- consistent components
- smooth animation
- mobile first
- delightful

These may be goals or obligations, but they do not resolve a product-specific decision.

## Principle conflicts

When principles conflict:

1. protected product truth wins
2. user outcome wins over visual novelty
3. safety and recovery win over speed
4. repeated-use cost wins over one-time ceremony
5. platform familiarity wins unless custom behavior materially improves the core experience
6. document the tradeoff rather than weakening both sides

## Use during review

For every major design decision ask:

- Which principle supports this?
- Which credible alternative did it reject?
- Is the principle visible in the behavior, not only the explanation?
- Has the implementation drifted from it?

If a principle never changes a decision, remove it.
