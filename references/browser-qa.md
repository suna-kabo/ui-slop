# Browser QA

Use one rendered refinement loop for the proof and the built interface, scaled to the affected workflow. Use realistic content and include a difficult record such as a long name, missing data, or a dense comparison. Load intended fonts and assets. Check real desktop and mobile sizes, with relevant keyboard, touch, color scheme, and reduced-motion settings.

## Inspect

Run the ten-second pass in `quality-bar.md` before considering design rationale. Inspect the first useful viewport and the weakest affected secondary state. Ask what the user notices first, what they need to compare or act on, and what falls outside the useful viewport.

## Operate

Follow the primary action through input, immediate feedback, transition or pending state, result, and continuation. Include a second action and return, retry, or reversal. Watch what happens during the change, including where focus and scroll go and which objects stay anchored. For a consequential transient state, use a recording, trace, or frame sample if endpoints miss what happened. When relevant, repeat or retarget before settlement and trigger an unrelated update to check that it leaves the interaction intact.

After a consequential change, follow the same record into another affected view if the task relies on that view. Check that shared facts agree and that legitimate differences, such as planned and actual times, are clear where users act on them. Reload or reverse when persistence or recovery matters.

## Correct and verify

Pick the defects that most affect the task. Change the responsible decision or implementation. For example, regroup crowded decision data before shrinking it, or fix state ownership when another view shows stale status. Where supporting copy is involved, use the mandatory supporting-copy subtraction pass in `quality-bar.md`.

Render the changed state again at the affected sizes and reoperate a neighboring action, including return or focus when at risk. If motion matters, watch it during repeat use and with reduced motion. Record the observation, correction, and verified effect in the existing review record. Stop when the required scope has no material defect or the correction budget is spent. Report any remaining defect or unavailable check under the applicable gate.
