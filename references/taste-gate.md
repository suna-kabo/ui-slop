# Taste Gate

Run this only after the Evidence Gate passes.

The goal is to detect polished genericness, aesthetic convergence, and under-designed restraint.

## Product specificity

Mentally remove the logo and product name.

Ask:

- Does the composition still make sense for this product specifically?
- Is the primary workflow visible in the structure?
- Could this exact shell be reused unchanged for analytics, CRM, finance, HR, and project management?

If yes, the design is category-interchangeable.

## Thesis fidelity

Can the UI be described in one specific sentence that explains:

- composition
- hierarchy
- density
- type character
- color direction
- interaction character

If the description collapses to "clean modern dashboard," the thesis failed.

## Aesthetic convergence

Compare against unrelated recent work.

Ask:

- Did I use the same dark/light foundation again without product reason?
- Did green, blue, or purple become the accent out of habit?
- Did the same rounded humanist font appear again?
- Did I reuse the same card/sidebar/right-rail skeleton?
- Did every product get the same motion vocabulary?

Similarity is allowed when justified.
Unconscious repetition is not.

## Typography

Ask:

- Is typography doing real work?
- Was the chosen direction compared against another credible option when the system was open?
- Are data, body, utility, and display roles appropriate?
- Is the result memorable without being decorative?

## Color

Ask:

- Is accent separate from semantic status?
- Is the palette grounded in the product?
- Would a different product likely receive the same palette from this model?
- Does the palette work without the logo?

## Composition

Ask:

- Is the best space given to the primary job?
- Are secondary utilities actually secondary?
- Did card containment replace real hierarchy?
- Is negative space creating focus or just emptiness?
- Does the wide viewport use width intentionally?

## Interaction

Ask:

- Is the product more satisfying and understandable in motion than in a screenshot?
- Does selection preserve context?
- Do contextual surfaces feel spatially related?
- Is motion authored or merely `transition: 150ms` everywhere?

Near-static products can pass when precision is intentional.

## Mobile

Ask:

- Is mobile a deliberate representation?
- Did priority change appropriately?
- Were wide tables transformed rather than merely squeezed?
- Did inspectors become a suitable mobile pattern?
- Did desktop whitespace become an endless vertical page?

## Restraint versus under-design

Removing cards, gradients, pills, icons, and filler is only the first step.

If what remains is merely a dark or light document with thin borders, the product is under-designed.

Replace decoration with:

- better proportion
- clearer hierarchy
- stronger typography
- more purposeful spacing
- interaction character
- product-specific structure

## Final verdict

A substantial design passes when a skilled reviewer is more likely to say:

> This feels intentionally designed for what it does.

than:

> This is clean.

If not, revise.


## Human-care test

Ask:

- Does any detail show that the designer understood how this specific user spends time here?
- Are hover, selected, loading, empty, and detail states tailored to the object?
- Does the typeface feel chosen?
- Does the interface reveal more character after interaction?
- Would a fan/user of this domain recognize care rather than generic professionalism?

If not, the result may be polished but emotionally generic.

## Browsing-pull test

For browse-heavy products ask:

- Is there an obvious but non-coercive next interesting thing?
- Does section rhythm vary enough to sustain attention?
- Are related items/collections discoverable?
- Do hover/detail transitions reward exploration?
- Does the visual system help users form preferences and memory?

If every item uses an identical card/list template, browsing is probably too flat.

## Silhouette veto

If unrelated recent work has substantially the same:

- opening composition
- control placement
- right rail
- card geometry
- mobile transformation

the design fails unless shared structure is justified by the workflow.

Different color and typography cannot rescue a repeated shell.
