# UI Acceptance Checklist

Use this before declaring a substantial UI task complete.

## Product hierarchy

- Can a new user identify the primary task quickly?
- Are secondary utilities visually secondary?
- Is important evidence closer to the decision it supports?
- Are there controls that exist only because the old UI had them?

## Anti-slop review

- Any unnecessary card grids?
- Any giant heading or hero area inside working software?
- Any decorative gradient or glow without meaning?
- Any badge/pill overload?
- Any meaningless icons?
- Any repeated subtitle/helper pattern?
- Any generic SaaS/admin layout chosen without a product reason?

## Writing review

- Any implementation language exposed to users?
- Any defensive disclaimer that can be removed?
- Any obvious instruction that should be solved through affordance?
- Any filler prose occupying space?
- Any internal term that should be renamed?

## Typography

- Was the typeface evaluated in the real UI?
- Is small text readable?
- Are numbers clear and aligned where needed?
- Does the font feel mature rather than corporate-industrial or childish?
- Does it survive 200% text scaling?

## Layout

- Does 1920 or 1440 use space intelligently?
- Does 1280 remain composed?
- Is tablet intentionally designed?
- Is mobile intentionally redesigned rather than stacked?
- Any dead space that makes the UI look unfinished?
- Any density that causes fatigue?

## Interaction

- Hover states clear?
- Pressed states present?
- Selected state obvious?
- Focus visible?
- Back/Forward coherent?
- Detail surfaces restore focus?
- Motion fast and purposeful?
- Reduced motion usable?

## Accessibility

- Keyboard works end to end?
- Accessible names accurate?
- Contrast sufficient?
- Critical meaning not color-only?
- 200% reflow acceptable?
- 320 px layout usable when relevant?
- Touch controls usable on mobile?

## Performance

- Initial render responsive?
- Long lists scroll smoothly?
- Filtering and sorting responsive?
- No expensive decorative animation?
- No unnecessary large frontend dependency added for small effects?

## Final judgment

Ask all of these:

- Does it feel purpose-built?
- Does it feel visually calm but not empty?
- Does it feel polished but not decorative?
- Does it feel distinctive without depending on novelty?
- Would someone want to keep it open for hours?
- Does anything still look like generic AI-generated UI?

If the last answer is yes, continue iterating.
